## [DISCOVERIES]
- 2026-10-16T16:07Z [CODE] Version 3 dictionaries use 4-byte encoded words padded to six Z-characters; negative entry counts indicate an unsorted user dictionary. Parse entries store dictionary address, token length, and one-based text-buffer position.
- 2026-10-16T15:47Z [CODE] Version 3 property headers encode lengths 1–8 in their upper three bits and property numbers 1–31 in their lower five; attributes are stored most-significant-bit first. Property lists descend by property number.
- 2026-10-16T16:24Z [CODE] Variable-form `je` supports two through four operands; opcode execution defers variable reads so indirect stack targets are not consumed as values. `verify` checks the immutable loaded image because runtime writes can change dynamic memory.
- 2026-10-16T16:43Z [CODE] Version 3 read consumes host-completed lines, stores lower-case text and tokenizes it; hosts own editing. Stream 3 nests up to 16 tables and suppresses streams 1/2 while selected. Transcript and command-file streams are optional host capabilities; restart preserves Flags 2 bits 0–1.
- 2026-10-16T17:39Z [TOOL] ZSpec 1.1 requires v3 status refresh only for `show_status` and before `read`; its lower window scrolls upward and upper window clears on split without scrolling. Task 13 sets Flags 1 bit 5 to advertise supported window splitting.

- 2026-10-16T05:55Z [TOOL] Z-Machine Standard 1.1 specifies v3 file-length units of 2 bytes, checksum coverage from byte 0x40 to logical file length, a 128 KiB v1-v3 size limit, and legacy v3 files that may omit length/checksum.
- 2026-10-16T14:59Z [TOOL] Version 3 packed addresses expand by 2 and may reach 131070 bytes in 128 KiB stories; interpreter reads therefore must reach beyond 64 KiB. Version 3 Flags 1 interpreter-controlled bits are 4–6; Flags 2 game-controlled bits are 0–1, with bit 2 clear-only for game writes.
- 2026-10-16T15:06Z [TOOL] Version 3 uses the default A0/A1/A2 alphabets; A2 z-characters 6 and 7 are the ZSCII escape and newline, so the alphabet's stored positions must retain placeholders for both.
- 2026-10-16T15:23Z [TOOL] Instruction forms are distinguished by the top two bits: `$00–$7F` long, `$80–$BF` short, and `$C0–$FF` variable. Variable zero pops for value reads and pushes for result stores; indirect operations inspect or replace the existing stack top.
- 2026-10-16T18:15Z [CODE] IFF identifiers must be validated from raw bytes before ASCII decoding; .NET ASCII replacement fallback can turn non-ASCII bytes into printable `?`. IFZS framing uses exact FORM bounds, big-endian chunk lengths, and required zero padding for odd data.
- 2026-10-16T18:24Z [CODE] CMem stores XOR differences; a zero run encodes 1–256 unchanged bytes. Decoding may stop early and fills the remaining tail from original memory, but rejects incomplete runs and any output beyond dynamic memory. UMem requires exact length.
- 2026-10-16T19:58Z [CODE] A host save requested while the Z3 executor is awaiting a command must record the current `read` instruction address as its direct-resume PC; otherwise restore skips reading the next command.
